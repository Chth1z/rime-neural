# Architecture & Design Notes (`rime-neural` v1.1.0)

## 1. Zero-Patch In-Process Execution Model

Official Weasel (`librime >= 1.17.0`, Lua 5.4.8) exports the Lua 5.4 C API directly from `rime.dll` and permits `package.loadlib`.

- **`src/lua_api.rs`**: Dynamically resolves the 21 required `lua_*` symbols (including `lua_version`, `lua_checkstack`, `lua_gettop`, `lua_rawget`, and `lua_rawset` for metamethod-free table access) from `GetModuleHandleA("rime.dll")` (with `librime.dll` fallback) with zero import `.lib` dependency. Verifies `lua_version(L) >= 504.0` before executing any closure, checks `LUA_TSTRING` before `lua_tolstring` to avoid in-place stack mutation, and verifies `GetModuleHandleExA(PIN | FROM_ADDRESS)` succeeds before returning the module table so Rime redeploys (`lua_close` -> `FreeLibrary`) never unload active ONNX Runtime worker pools or the UIA worker thread. All `extern "C"` entry points are wrapped in `catch_unwind`.
- **`lua/rime_neural.lua`**: Calls `init_async(...)` so `WeaselServer.exe` startup incurs `0 ms` delay while ONNX Runtime loads in a background thread. Tracks failed DLL paths per path, retains the loaded native handle for cross-schema retries, lazily attaches `.gram` once readiness completes, and preserves rerank snapshots across trailing punctuation auto-commits (`,`, `.`, `?`, `!`, `:`, `;`) while clearing stale snapshots on partial-segment selection. Supports an optional `rime_neural/data_dir` override and `shared_data_dir\neural` fallback for non-ASCII Windows user profile paths, while always keeping `feedback.jsonl` under the writable `user_dir\neural\` via Rust's UTF-16 Win32 APIs.

## 2. Inference Pipeline (`src/engine.rs`)

1. **Strict `sentence`-Only Gating**: Only contiguous leading candidates with `cand:get_genuine().type == "sentence"` and matching `(start, _end)` are reranked. Exact dictionary phrases (`phrase`), userdb phrases (`user_phrase`), English words, dates, numbers, mixed uppercase/digit/auxiliary-code inputs, and punctuation are passed through unchanged.
2. **Dynamic Model Architecture Introspection & Fast Cold Start**:
   - Inspects `past_enc_k` and `past_choice_k` shapes directly from `session.inputs()` (`[enc_layers, 1, heads, p, head_dim]` and `[choice_layers, 1, heads, p, head_dim]`), checks `choice_compact` in `unified_vocab.json`, and derives the no-prepend candidate tokenizer via in-memory `tokenizer.clone()` + `Metaspace(PrependScheme::Never)` (avoiding re-parsing the 32 MB `tokenizer.json`).
   - Collects all special/control added tokens from `tokenizer.get_added_tokens_decoder()` at startup and strips/filters them from untrusted UIA context and candidate text before/after `encode_fast`.
   - Configures sequential execution with single inter-op thread (`with_parallel_execution(false)`, `with_inter_op_spinning(false)`) while preserving intra-op spinning for sub-2 ms burst keystroke latency.
   - Pre-builds 3 selective `ort::RunOptions` via `OutputSelector::no_default()`:
     - Context KV pass: fetches only `present_enc_k/v` + `present_choice_k/v`
     - Pass-1 keystroke: fetches only `logits` + `char_logits` (avoiding ~3 MB/keystroke unused KV output copies)
     - Pass-2 P2C verification: fetches only `logits`
   - Reuses per-engine `i64` / `String` scratch buffers via `TensorRef::from_array_view`, decodes `char_logits` directly from ORT's borrowed slice with precomputed per-slot allowed-char tables, and merges `uv.ml.pinyin` into `readings` (+2,737 Traditional/variant/extended Hanzi) while keeping `old_chars` capping Simplified P2C generation.
3. **16-Slot Token-ID Prefix KV-Cache + 256-Entry Monotonic-Clock LRU**: Keys prefix KV entries on truncated context token IDs (with empty context pinned and a single shared `true_mask` slice on the engine). Evaluation cache uses an in-place monotonic `u64` LRU clock (halving cache key memory and making cache-hit promotion O(1)), covering canonicalized weights, `p2c_verify_margin`, context, raw input, layout, and candidates.
4. **Zero-Extra-RAM Single-Pass `.gram` Fusion (`src/gram.rs`)**: Memory-maps `Rime::Grammar/1.0` (`wanxiang-lts-zh-hans.gram`) read-only via Win32 `CreateFileMappingW` with `FILE_FLAG_RANDOM_ACCESS` and strict checked header validation (`0 MB` extra physical RAM). Uses a single-pass forward double-array trie walk (`~0.004 ms`/sentence, zero per-char heap allocations) bit-identical to `octagram.cc`, and reuses Pass-1 `.gram` scores during Pass-2 P2C verification.
5. **5-Feature Cross-Domain Linear Fusion**:
   $$s_i = w_0 \cdot \log\operatorname{softmax}(\text{logit})_i + w_1 \cdot \ln(i + 1) + w_2 \cdot \Delta_{\text{gram}, i} + w_3 \cdot \Delta_{\text{char\_lp}, i} + w_4 \cdot \mathbb{1}_{\text{ctx}} \cdot \log\operatorname{softmax}(\text{logit})_i$$
   Default weights: `[1.0, -1.4, 0.05, 0.15, 0.0]`.
6. **KV-Cached Pass-2 Verified P2C Synthesis**: Strictly gated on `all_same_len` (candidate lengths matching slot count) to prevent mismatched-length hallucinations. Only when the synthesized string is novel and beats Rime's best `char_logits` margin by `verify_margin` (~7% of sentences), runs a lightweight 3-candidate Pass-2 check reusing the warm prefix KV-cache, Pass-1 candidate token IDs, and `.gram` floor (`top1_logit_diff > 2.0` and `gram_delta > -2.0` for #1; `top2_logit_diff > 0.5` for #2).

## 3. Universal Pinyin Recovery (`src/pinyin.rs`)

- **7 Double Pinyin layouts**: Natural (ZRM), Flypy (小鹤), MSPY (微软, `; = ing`), Sogou (搜狗, `; = ing`), ABC (智能ABC), Ziguang (紫光, `; = ing`), Jiajia/PYJJ (拼音加加). Exhaustively verified against all 3,008 derived 2-key codes in official `rime-ice` / `rime-frost` schemas, respecting explicit `'`/` ` chunk separators and maintaining 1:1 slot alignment on invalid pairs.
- **Full Pinyin**: Memoized `O(N * L)` alignment against the leading candidate's merged `readings`, respecting explicit `'` and space syllable separators, mapping `lue`/`nue` and `[jqxy]v*` user aliases to canonical vocabulary syllables, supporting bounded adjacent-letter transposition recovery (`yuo->you`, `xaing->xiang`, `hoa->hao`, etc.), and preventing non-standard syllabic fragments (`m`/`n`/`ng`/`o`) from masquerading as full syllables during greedy fallback.

## 4. Non-Blocking, Fail-Closed UIA Context (`src/uia.rs`)

- All COM / UIA work runs on one dedicated background MTA (`COINIT_MULTITHREADED`) thread using `CUIAutomation8` / `IUIAutomation6` with 200 ms connection and transaction timeouts; throttled same-window refresh triggers schedule a trailing deferred probe (`recv_timeout`) so focus moves into password controls are never dropped.
- Pre-warmed asynchronously on keystrokes 1–2, and refreshed after commits via `kick_uia_after_commit()` (25 ms off-thread settle delay bypassing the 35 ms keystroke throttle).
- Clamps `IUIAutomationTextPattern` ranges strictly inside `RangeFromChild(&focused)` (rejecting out-of-element carets where `end_inside < 0` and failed `MoveEndpointByUnit` calls), reads up to 512 UTF-16 code units before the caret, breaks on `U+FFFC` and whitespace-only blank lines, strips invisible zero-width format characters and `U+FFFD` surrogate artifacts, returns an atomic `(UiaContext, hwnd, preedit_stripped)` tuple so Lua never double-strips genuine Traditional context, and detects bullet-masked password controls (`••••••`/`******`).
- Synchronously tracks foreground `HWND` and `(hwnd, pid)` denylist cache, verifies focused element root ancestry (`GetAncestor(..., GA_ROOT)`) and post-read foreground `HWND`.
- Fails closed on `CurrentIsPassword == true` (hard block), `CurrentIsPassword` COM error (refuses UIA read), `OpenProcess` `ERROR_ACCESS_DENIED` (Protected Processes / hardened credential UIs), and password managers / credential UIs / remote-session clients (`KeePass`, `KeePassXC`, `1Password`, `Bitwarden`, `Enpass`, `LastPass`, `Dashlane`, `RoboForm`, `NordPass`, `ProtonPass`, `Keeper`, `PasswordSafe`, `Authy`, `WinAuth`, `CredentialUIBroker`, `consent.exe`, `LockApp`, `mstsc.exe`, `msrdc.exe`, `PuTTY`, `Xshell`, `MobaXterm`, `FinalShell`).

## 5. Zero-Plaintext Feedback & Personal MAP Tuning (`src/feedback.rs` + `scripts/tune-fusion.py`)

- Captures pre-OpenCC genuine Simplified candidate text strictly for the reranked segment range `[seg_start, seg_end)` in memory, resolves candidate indices, and writes only zero-plaintext numeric feature records (`v: 2`, `sample_weight = 1.0`, `model`, `has_gram`, capped candidate/string sizes, symlink rejection, atomic `MoveFileExW` 5 MiB rotation).
- `scripts/tune-fusion.py` reads both `feedback.jsonl` and rotated `feedback.jsonl.1` (with `--schema` / `--model` filters and `--scrub-legacy-inplace` to convert pre-v2 logs atomically), runs damped Newton-Raphson Bayesian MAP shrinkage (`(lam / sum_w) * 0.5 * ||w - W_PRIOR||^2`) with Armijo backtracking line search around `W_PRIOR`, selects `lam` by contiguous blocked 5-fold out-of-fold weighted log-loss (NLL), and gates updates on `min(N, Kish N_eff) >= 100`, a one-sided paired 95% CI test (`z >= 1.645`, Hajek sandwich SE), non-decreasing Top-1 accuracy, and domain sanity bounds (`w_logit >= 0.1`, `w_rank <= 0.0`, `w_logit + w_ctx_lp >= 0.1`).

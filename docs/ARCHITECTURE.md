# Architecture & Design Notes

## 1. Zero-Patch In-Process Execution Model

Official Rime hosts (`librime >= 1.17.0`, Lua 5.4, including Windows Weasel and Unix/macOS `librime-lua` frontends) export the Lua 5.4 C API directly and allow `package.loadlib`.

- **`src/lua_api.rs` & `build.rs`**:
  - **Windows**: Probes `rime.dll` (falling back to `librime.dll`, `lua54.dll`, and the current executable), requiring Lua 5.4-exclusive `lua_newuserdatauv` alongside the 21 required `lua_*` symbols (`lua_version`, `lua_checkstack`, `lua_gettop`, `lua_rawget`, `lua_rawset`, etc.) without `.lib` import linkage. Enforces `(504.0..505.0)` from `lua_version(L)` before pinning the DLL via `GetModuleHandleExA(PIN | FROM_ADDRESS)`. `build.rs` embeds Win32 `VS_VERSION_INFO` into `rime_neural.dll`.
  - **Unix / macOS**: Locates `lua_newuserdatauv` via `dlsym(RTLD_DEFAULT, ...)`, identifies the owning DSO via `dladdr`, pins both the Lua provider and `librime_neural` via `dlopen(..., RTLD_NOW | RTLD_NOLOAD | RTLD_NODELETE)`, and resolves all 21 Lua 5.4 symbols strictly from that single provider (verifying matching `dli_fbase` so mixed Lua 5.3/5.4 providers are rejected fail-closed).
  - All Lua C bindings and entry points use `extern "C-unwind"` with `catch_unwind` boundaries (`panic = "unwind"` in `[profile.release]`).
- **`lua/rime_neural.lua`**: Resolves platform-specific native module names (`rime_neural.dll` / `librime_neural.dylib` / `librime_neural.so`) and ONNX Runtime shared libraries with host path normalization, starts `init_async(...)` on a background thread, and shares the loaded native handle, resolved schema layouts, and `.gram` request metadata via `package.loaded` with `lua/rime_neural_repair.lua`.

## 2. Inference Pipeline (`src/engine.rs`)

1. **Strict `sentence`-Only & Tag Gating**: Only contiguous leading candidates on configured segment tags (default `["abc"]`) with `cand:get_genuine().type == "sentence"` and matching `(start, _end)` are reranked. Exact dictionary phrases (`phrase`), userdb phrases (`user_phrase`), English words, dates, numbers, mixed uppercase/digit/auxiliary-code inputs, and punctuation pass through unchanged.
2. **Dynamic Model Architecture Introspection & Fast Cold Start**:
   - Inspects `past_enc_k` and `past_choice_k` shapes from `session.inputs()` (`[enc_layers, 1, heads, p, head_dim]` and `[choice_layers, 1, heads, p, head_dim]`), verifies required ONNX output names (`logits` and all 4 `present_*` tensors), checks `choice_compact` in `unified_vocab.json`, and builds the no-prepend candidate tokenizer in memory across `PreTokenizerWrapper::Sequence`.
   - Collects special/control added tokens from `tokenizer.get_added_tokens_decoder()` into a dynamic first-byte trigger table, stripping control tokens from untrusted context and candidate text while preserving ordinary vocabulary tokens (`<code>`, `<b>`, `<unk>`).
   - Configures sequential execution (`with_parallel_execution(false)`, `with_inter_op_spinning(false)`) and pre-builds 3 selective `ort::RunOptions` via `OutputSelector::no_default()` (context KV pass, Pass-1 keystroke, Pass-2 verification).
   - Reuses per-engine `i64` / `String` scratch buffers via `TensorRef::from_array_view`, decodes `char_logits` directly from ORT's borrowed slice with partition cancellation for in-vocabulary comparisons, merges `uv.readings` and single-char entries of `uv.ml.pinyin`, and suppresses `char_lps` on alternate segmentations.
3. **16-Slot Token-ID Prefix KV-Cache + 256-Entry Monotonic-Clock LRU**: Caches `(last_ctx_str, last_ctx_ids)` and keys prefix KV entries strictly on truncated short-context token IDs (`<= 128 chars`, never including the 1,024-char entity buffer). The evaluation LRU cache uses an in-place monotonic `u64` clock keyed by canonicalized weights, `p2c_verify_margin`, active `.gram` configuration, short context, optional document entity context, raw input, layout, and candidates.
4. **Single-Pass `.gram` Fusion (`src/gram.rs`)**: Reads `Rime::Grammar/1.0` (`wanxiang-lts-zh-hans.gram`) with header and bounds validation, sharing one reader per loaded path across schemas with per-schema penalties and `collocation_max_length` (`2..=8`). Uses kernel-pinned read-only `CreateFileMappingW` + `MapViewOfFile` (`FILE_FLAG_RANDOM_ACCESS`) on Windows and an immutable owned `Vec<u32>` snapshot on Unix/macOS (immune to in-place file truncation `SIGBUS`). Scores each sentence in `~0.004 ms` via a single-pass forward double-array trie walk bit-identical to upstream `librime-octagram` across BMP and non-BMP UTF-8 (`〇`, CJK Ext A–I).
5. **5-Feature Cross-Domain Linear Fusion**:

   $$s_i = w_0 \cdot \log\operatorname{softmax}(\text{logit})_i + w_1 \cdot \ln(i + 1) + w_2 \cdot \Delta_{\text{gram}, i} + w_3 \cdot \Delta_{\text{char\_lp}, i} + w_4 \cdot \mathbf{1}_{\text{ctx}} \cdot \log\operatorname{softmax}(\text{logit})_i$$

   Default weights: `[1.0, -1.4, 0.05, 0.15, 0.0]`.
6. **KV-Cached Pass-2 Verified P2C Synthesis & Focus-Bound Context / Document Entity Splice**: Requires full syllables, finite scores, and candidate lengths matching the slot count. When Pass-2 verification is enabled (`verify_margin > 0`), the engine batches up to 4 deduplicated proposals into a single KV-cached Pass-2 forward pass reusing Pass-1 candidate tokens:
   - **Greedy P2C proposal**: included when the novel `char_logits` string beats Rime's best candidate by `verify_margin`, placed at `#1` when `ldiff > top1_logit_diff && gdiff > top1_min_gram_diff` (or `#2` when `ldiff > top2_logit_diff && gdiff > top1_min_gram_diff - 1.5`).
   - **Maximal Context & Document Entity Splices**: scans left- and right-maximal 2+ character reading-matched Han spans from the active short context (`ctx_tail`, with `+2.0`/`+1.5` prefix-copy bias guard) and, when opt-in `enable_document_entities: true` is enabled, from up to 1,024 preceding characters in the same focused control (`entity_tail`, scanned without adding KV prefix tokens). Each verified proposal is cached with its origin and evaluated independently in `select_p2c_placement`.

## 3. Universal Pinyin Recovery & 1-Edit Typo Lattice (`src/pinyin.rs`, `src/typo.rs`)

- **7 Double Pinyin layouts**: Natural (ZRM), Flypy (小鹤), MSPY (微软, `; = ing`), Sogou (搜狗, `; = ing`), ABC (智能ABC), Ziguang (紫光, `; = ing`), Jiajia/PYJJ (拼音加加), verified against all 3,008 derived 2-key codes in official `rime-ice` / `rime-frost` schemas.
- **Full Pinyin**: 3-phase ordered memoized `O(N * L)` alignment (exact full syllable -> bounded adjacent-letter transposition across readings and user aliases -> ASCII partial prefix) with `lue`/`nue`/`[jqxy]v*` alias support and an `O(L)` dynamic-programming fallback splitter.
- **Automatic 1-Edit Typo-Tolerant Lattice (`src/typo.rs` + `lua/rime_neural.lua`)**:
  - **Live-prefix protection**: `is_live_pinyin_prefix` verifies whether the raw keystream is a valid syllable sequence or a legal mid-word prefix (Full Pinyin syllable prefix, explicit apostrophe abbreviations, or trailing odd Double Pinyin initial) in `~1 µs`. Clean typing and in-progress prefixes return empty immediately with zero translator queries, zero UIA lookups, and zero extra ONNX passes.
  - **Proven-dead recovery**: Only when a chunk fails strict parsing (excluding vowelless interjections `m`/`n`/`ng`/`hm`/`hng` inside continuous Full Pinyin), `suggest_broken_input_repairs` searches staggered QWERTY physical neighbor substitutions, adjacent transpositions, doubled-key deduplication, and dropped-key insertions (for both Full Pinyin and odd-length Double Pinyin) within the failing window.
  - **Read-only dictionary + `.gram` + neural verification**: Queries a dedicated read-only `rime_neural_lookup` `script_translator` (`enable_user_dict: false`, `enable_encoder: false`, `enable_correction: false`, copying `dictionary`, `prism`, `packs`, `max_homophones`, `max_sentences`, and `sentence_cutoff_threshold`, scanning at most 48 candidates per spelling). Requires active `.gram` evidence (`score_gram` returns `(scores, has_gram)`), filters individual candidates through per-char and length-scaled total fluency gates before neural selection, and suppresses feedback logging on recovered commits.

## 4. Non-Blocking, Fail-Closed UIA Context (`src/uia.rs`)

- On Windows, all COM / UIA work runs on one dedicated background MTA (`COINIT_MULTITHREADED`) thread using `CUIAutomation8` / `IUIAutomation6` with 200 ms timeouts and an `IUIAutomationFocusChangedEventHandler` for immediate snapshot invalidation on focus moves. On non-Windows hosts, `query_context` returns `UiaContext::Unavailable` rather than fabricating a verified focus identity.
- Standard capture walks back up to 96 characters (`GetText(512)`) inside `RangeFromChild(&focused)` (falling back to `DocumentRange`) and retains up to 64 characters in the active paragraph. When opt-in `enable_document_entities: true` is active, the worker walks back up to 1,024 characters (`GetText(2048)`) within the same focused-control and `U+FFFC` boundaries, keeping the active paragraph (`<= 64 chars`) for KV-cache scoring while separating earlier paragraphs into `entity_text` (`<= 1,024 chars`). Opting out, switching schemas, toggling reranking off, or unloading resets the flag and immediately invalidates retained snapshots.
- Masked-password heuristics run on both the full captured string and the 96-character near-caret tail, alongside `CurrentIsPassword == true`, `E_ACCESSDENIED`/COM errors, `OpenProcess` `ERROR_ACCESS_DENIED`, and the sensitive-process denylist (password managers, authenticators, credential/UAC UIs, remote-session clients, and local terminals).

## 5. Zero-Plaintext Feedback & Personal MAP Tuning (`src/feedback.rs` + `scripts/tune-fusion.py`)

- At commit, the filter matches the input prefix and selected candidate's byte range to the scored segment, reading the final Rime menu's displayed rank and genuine pre-OpenCC sources (skipping ambiguous merges and synthesized `rime_neural_*` repair/typo candidates). Writes zero-plaintext numeric feature records (`v: 2`, `num_cands <= 64`) with `FILE_FLAG_OPEN_REPARSE_POINT` (Windows) or `O_NOFOLLOW | O_NONBLOCK` (Unix) plus opened-handle regularity verification, rotating atomically at 5 MiB (1 `.1` backup, 10 MiB transient-lock cap).
- `scripts/tune-fusion.py` runs damped Newton-Raphson Bayesian MAP shrinkage (`(lam / Kish N_eff) * 0.5 * ||w - W_PRIOR||^2`) over five contiguous held-out blocks with per-fold `w_ctx_lp` freezing, three-decimal evaluation, Bonferroni one-sided paired NLL testing (`z >= 2.450`, Hájek SE), non-decreasing Top-1 accuracy, and domain weight constraints.

## 6. Opt-In Pre-Commit Full-Dictionary Neural Span Repair & Literal Lock (`lua/rime_neural_repair.lua`)

- Mounted optionally at `engine/processors/@before 0` with configurable hotkeys (`rime_neural_repair/repair_key`, default `Alt+r`; `rime_neural_repair/lock_key`, default `Alt+l`; empty string disables individually). Idle keystrokes perform at most two `KeyEvent:eq` comparisons before returning `kNoop`.
- **Full-dictionary + 1-edit typo + neural-ranked chained pre-commit repair (`Alt+r`)**:
  - Maintains two coordinate spaces per word (`lo..hi` immutable byte bounds + `typed_raw` in `ctx.input`, paired with mutable `lookup_raw` and `draft_text`) so chained multi-word repairs inside the same sentence preserve exact original byte boundaries across repeated `Alt+r` invocations.
  - Collects alternatives across three tiers: native menu `Sentence` homophones (preserving native `seg.selected_index` selection when unchained), exact-span matches from a lazy read-only `rime_neural_lookup` `script_translator` (`enable_user_dict: false`, with `packs` copied), and 1-edit span typo neighbors from `suggest_typo_inputs(..., "span", 20)` (recovering valid-syllable slips such as ZRM `gsye -> gsyr` and Full Pinyin `jintan -> jintian`).
  - Ranks exact-spelling homophones in full-sentence context via a single Pass-1 `ML-pumpkin-1103` + `.gram` call using session- and focus-epoch-validated context (falling back strictly to confirmed segments in the current composition), and scores competing typo spelling groups under their own corrected spellings so phonetic conditioning matches (`gsye -> gsyr -> 公园`).
  - Applies the schema's active OpenCC output conversion (e.g. Traditional output) to rendered overlay hints and synthetic pre-commit draft candidates while retaining Simplified source strings for neural/`.gram` ranking; `Escape` / toggle reverts cleanly to the exact pre-repair menu and selection.
- **Verbatim ASCII literal lock (`Alt+l`)**: arms at an empty composition, after confirmed/selected prefix segments (confirming a fully covering `sentence`, repaired draft, or auto-typo candidate in place mid-composition), or locks a pending ASCII token (`[A-Za-z0-9._/%-+]`) as a native `kConfirmed` `raw` segment with `BackSpace` editing and automatic disarm on external context updates.
